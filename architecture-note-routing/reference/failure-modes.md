# Seven ways a routing pass makes the docs tree worse

Each of these produces a document that reads as authoritative and gets cited.
That is why the corresponding rules in SKILL.md are rules and not preferences —
the defect is not visible in the document that carries it.

**Invented detail.** The fragment leaves the storage layer unspecified; the
document names one to read smoothly. It is now the documented architecture, will
be cited in a decision record, and no trace remains that it was a guess.

**Duplication as convenience.** A glossary definition is restated inline "so the
reader doesn't have to click". The two copies diverge on the next rename and the
reader now has two definitions and no way to tell which is current.

**Empty scaffolding.** A file is created because the topic ought to exist. It
sits at fifty words for a year, reads as coverage, and stops anyone writing the
real thing.

**Silent reconciliation.** The fragment disagrees with an existing document and
the pass smooths it over. The disagreement was the signal — it was either a
decision nobody recorded or a drift nobody noticed, and both are now invisible.

**The decision buried in prose.** A paragraph in an architecture document
quietly closes off an option. It is unnumbered, unindexed, has no rejected
alternatives, and nobody can find it later.

**Terminology drift.** New prose uses a term the glossary defines differently.
Fixing the prose to match the glossary is right; fixing neither is what usually
happens, and after three passes no two documents mean the same thing.

**Refining raw source upward without purpose.** Raw capture gets rewritten into
polished prose nobody needed, and the original wording — which was the evidence
— is gone.
