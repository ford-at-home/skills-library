# How this goes wrong

**The one it exists to catch.** The page is up, so the next question is what to
add to it, and each addition sounds small. Auth, then a dashboard behind the
auth, then a database behind the dashboard. Three weeks later the demand test is
an unfinished product and still has no signal, because nobody ever agreed what
number would settle it. The refusal table is the whole defense and it only works
if it was written first.

**The promise nobody checked.** Copy written to be persuasive drifts into present
tense — features described as available, a headline stating the outcome as fact.
Nobody lied at any single step; the claim inventory is what catches it, because
it forces each sentence to be checked alone rather than read as a paragraph.

**Placeholder proof in production.** Template social proof and testimonial
skeletons pass review because they read as layout rather than as claims. The
check is whether you could name the people.

**Silent capture failure.** The success message is client-side and fires whether
or not anything was stored. Tested only in preview, or only on the happy path,
this reads as zero demand for weeks.

**Testing four assumptions at once.** The page bundles the pain, the solution, the
price, and the channel. Nobody signs up and there is no way to learn which one was
wrong. Step 1 asks for one assumption for this reason.

**Confusing traffic with demand.** Signups get read as a rate without knowing how
many people saw the page, or the page is judged after one share with people who
already like the idea. Record where the traffic came from, or the number only
tells you your friends are supportive.
