# Six ways this review appears to succeed and does not

**The one it exists to catch — metric satisficing.** Output metrics sit inside
target while the premise has collapsed. The metrics keep reporting health because
the team narrowed what it measures to the part that still works, usually without
deciding to. Nothing is hidden and nobody is lying. The only thing that catches it
is checking external evidence before metrics and letting external evidence win,
which is why the process ordering is not a preference.

**Tenet absence laundering.** Tenets synthesized by the reviewer and then presented
as the team's own. The ratification flag exists for exactly this and gets stripped
because it is inconvenient.

**Soft continue.** `continue` returned with several unknown tenets and no named
monitoring. Unknown tenets are acceptable only when something is actively watching
them.

**Pivot as kill avoidance.** `pivot` when the honest answer is `kill`, because the
team has capital invested. The drift narrative is the check: if the pivot hypothesis
is a different initiative wearing the same name, that is a kill.

**Escalate as decision avoidance.** `escalate` because the reviewer is
uncomfortable rather than because the authority genuinely sits higher. If you cannot
name a target and a specific question, you are not escalating.

**Tenet narrowing.** The most common failure in practice. At review time the tenet
is quietly reinterpreted to match the evidence that exists, so it passes.
