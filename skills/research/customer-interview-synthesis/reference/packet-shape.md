# Synthesis packet shape

```markdown
# Interview Synthesis
**Target artifact:** <proposal | business case | exploratory>
**N:** <count> (transcripts <n>, surveys <n>, notes <n>)
**Sample floor:** <n> transcripts — <the default, or why it was set here>
**Hypothesis going in:** <as stated by the team>
**Proposal ready:** <true | false> — <blockers if false>

## Read first
<Anything that changes how the rest should be read: the panel came from the
team's network, the floor was not met, all evidence is attitudinal.>

## Segments
### <label> — n=<supporting> · <tag>
- Behavioral: <claim> — "<quote>" (<R#>)
- Attitudinal: <claim> — "<quote>" (<R#>)
- Conflicts with: <segment, and why the disagreement matters>

## Problem
- Stated: <what they said> — "<quote>" (<R#>)
- Inferred underlying: <the reading> `[inference]` · Basis: <the quotes>

## Current workarounds
| Workaround | Count / N | What switching away appears to cost | Citation |
|---|---|---|---|

## Hypothesis status
- Supported by evidence: <true | false — strictly per evidence>
- Evidence for: <cited> · Evidence against: <cited; if empty, say so and flag it>

## Bias flags
| Pattern | Citation | What it does to the conclusions |
|---|---|---|

## Assumptions to resolve
| Assumption | Tag | What evidence would convert it to fact |
|---|---|---|

## Map to the proposal
| Proposal field | Which finding fills it | Source |
|---|---|---|
| customer | <a specific segment, not a category> | |
| problem | | |
| current workaround | | |
| desired outcome | | |
| open questions | | |
```

The floor is in the header because it is a claim about what this packet was gated
against. Two packets with the same N and different floors were held to different
standards, and a reader comparing them cannot see that anywhere else.

"Read first" carries anything that changes how the rest should be read, because a
packet gets skimmed from the middle. A caveat placed only in a methodology section
at the end is a caveat nobody reads before quoting the segments.

The map to the proposal names a specific segment for the customer field. A
category — "engineering leaders", "small teams" — is what a proposal fails on
later, and it passes review because it sounds like an answer.
